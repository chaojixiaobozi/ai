# i18n 配置分析与优化建议

## 一、当前配置详细分析

### 1) 你的 i18n 配置参数解析

```ts
i18n: {
  baseUrl: process.env.API_BASE_URL,           // 基础 URL，用于生成语言切换链接
  // strategy: 'prefix',                       // 路由策略（已注释）
  locales,                                     // 语言列表（18个语言）
  defaultLocale: 'en',                         // 默认语言
  detectBrowserLanguage: {                     // 浏览器语言检测
    cookieKey: `${storageKey}_i18n_redirected`, // Cookie 键名
    fallbackLocale: 'en'                       // 回退语言
  },
  vueI18n: '~/i18n/i18n.config.ts',           // Vue I18n 配置文件
  lazy: true                                   // 懒加载语言包
}
```

### 2) 各参数详细说明

#### baseUrl
- **作用**：用于生成语言切换链接的绝对 URL
- **当前值**：`process.env.API_BASE_URL`
- **影响**：影响 SEO 和语言切换链接的生成

#### strategy（已注释）
- **当前状态**：被注释掉，使用默认值 `'prefix_except_default'`
- **影响**：决定路由是否包含语言前缀

#### locales
- **当前值**：18个语言配置
- **包含语言**：ar, en, en-us, tl, fr, de, hi, id, it, ja, ko, ms, pt, ru, zh, es, sw, th, zh-hk, vi
- **影响**：每个语言都会影响路由生成和语言包加载

#### defaultLocale
- **当前值**：`'en'`
- **作用**：默认语言，当无法检测到用户语言时使用

#### detectBrowserLanguage
- **cookieKey**：存储语言检测结果的 Cookie 键名
- **fallbackLocale**：当检测失败时的回退语言
- **影响**：影响首次访问时的语言选择

#### vueI18n
- **当前值**：`'~/i18n/i18n.config.ts'`
- **作用**：Vue I18n 的配置入口
- **当前问题**：只配置了 `en` 语言包，其他语言为空对象

#### lazy
- **当前值**：`true`
- **作用**：懒加载语言包，按需加载
- **影响**：减少初始加载体积，但会增加运行时加载

## 二、strategy 配置详解

### 1) 可选的 strategy 值

#### `'prefix'` - 所有语言都有前缀
```ts
strategy: 'prefix'
```
- **URL 格式**：`/en/about`, `/zh/about`, `/de/about`
- **默认语言**：也有前缀 `/en/`
- **路由数量**：页面数 × 语言数
- **适用场景**：所有语言都需要 SEO 优化
- **性能影响**：路由数量最多，createRouter 最重

#### `'prefix_except_default'` - 默认语言无前缀（默认值）
```ts
strategy: 'prefix_except_default'
```
- **URL 格式**：`/about`（默认语言）, `/zh/about`, `/de/about`
- **默认语言**：无前缀
- **路由数量**：页面数 × (语言数 - 1) + 页面数
- **适用场景**：默认语言不需要前缀，其他语言需要
- **性能影响**：路由数量中等

#### `'prefix_and_default'` - 默认语言有前缀，但可无前缀访问
```ts
strategy: 'prefix_and_default'
```
- **URL 格式**：`/about` 和 `/en/about` 都指向默认语言
- **默认语言**：两种 URL 都支持
- **路由数量**：页面数 × 语言数 + 页面数
- **适用场景**：向后兼容，支持旧链接
- **性能影响**：路由数量最多

#### `'no_prefix'` - 无前缀
```ts
strategy: 'no_prefix'
```
- **URL 格式**：`/about`（所有语言）
- **语言切换**：通过 Cookie/Header/查询参数
- **路由数量**：页面数（最少）
- **适用场景**：语言切换不依赖 URL
- **性能影响**：路由数量最少，createRouter 最轻

### 2) 各策略对比

| 策略 | 路由数量 | SEO 友好 | 性能 | 推荐场景 |
|------|----------|----------|------|----------|
| `prefix` | 最多 | 最好 | 最差 | 全站多语言 SEO |
| `prefix_except_default` | 中等 | 好 | 中等 | 默认语言为主 |
| `prefix_and_default` | 最多 | 最好 | 最差 | 向后兼容 |
| `no_prefix` | 最少 | 一般 | 最好 | 性能优先 |

## 三、性能优化建议

### 1) 立即可执行的优化

#### 减少语言数量（开发环境）
```ts
// nuxt.config.ts
const isDev = process.env.NODE_ENV === 'development'
const locales = isDev 
  ? [{ code: 'en', language: 'en_GB' }]  // 开发环境只用英语
  : fullLocales  // 生产环境用全部语言
```

#### 使用 no_prefix 策略（性能优先）
```ts
i18n: {
  strategy: 'no_prefix',  // 路由数量最少
  // 其他配置保持不变
}
```

#### 优化语言包加载
```ts
// i18n/i18n.config.ts
export default defineI18nConfig(() => ({
  legacy: false,
  locale: 'en',
  fallbackLocale: 'en',
  messages: {
    en,  // 只保留默认语言
    // 其他语言通过 lazy 加载
  }
}))
```

### 2) 中期优化

#### 按需加载语言包
```ts
// plugins/i18n.loader.ts 优化
async function loadLanguagePack(locale: string) {
  // 添加缓存机制
  const cacheKey = `i18n_${locale}`
  const cached = sessionStorage.getItem(cacheKey)
  
  if (cached) {
    return JSON.parse(cached)
  }
  
  // 加载语言包
  const data = await $fetch(`/api/i18n/${locale}`)
  
  // 缓存到 sessionStorage
  sessionStorage.setItem(cacheKey, JSON.stringify(data))
  return data
}
```

#### 路由懒加载
```ts
// nuxt.config.ts
hooks: {
  'pages:extend'(routes) {
    // 对不常用页面进行懒加载
    routes.forEach(route => {
      if (route.path.startsWith('/admin')) {
        route.meta = { ...route.meta, lazy: true }
      }
    })
  }
}
```

### 3) 长期优化

#### ISR 缓存策略
```ts
// nuxt.config.ts
nitro: {
  routeRules: {
    // 按语言缓存
    '/': { isr: 300 },
    '/zh/**': { isr: 300 },
    '/de/**': { isr: 300 },
    // 其他语言...
  }
}
```

#### 语言包 CDN 化
```ts
// 将语言包放到 CDN
const loadLanguagePack = async (locale: string) => {
  const cdnUrl = `https://cdn.example.com/i18n/${locale}.json`
  return await $fetch(cdnUrl)
}
```

## 五、性能影响预估

### 当前配置（18语言 + prefix_except_default）
- **路由数量**：约 30-50 页面 × 18 语言 = 540-900 个路由
- **createRouter 耗时**：高（2-3秒）
- **内存占用**：高

### 优化后配置（no_prefix + 减少语言）
- **路由数量**：约 30-50 个路由
- **createRouter 耗时**：低（0.1-0.3秒）
- **内存占用**：低

### 性能提升
- **createRouter 耗时**：减少 80-90%
- **内存占用**：减少 70-80%
- **首屏加载**：提升 50-70%

## 六、实施建议

### 阶段一：立即优化（1-2天）
1. 开发环境减少语言数量
2. 使用 `no_prefix` 策略
3. 优化语言包加载

### 阶段二：中期优化（1-2周）
1. 实施 ISR 缓存
2. 优化语言包缓存机制
3. 路由懒加载

### 阶段三：长期优化（1-2月）
1. 语言包 CDN 化
2. 按需加载策略
3. 性能监控和调优

通过以上优化，你的 `createRouter` 性能问题应该能得到显著改善。
